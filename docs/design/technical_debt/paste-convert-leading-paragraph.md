# 技术债：粘贴结构块时保留前置空段落

状态：待解决。当前采用保留前置空行的方案，避开已复现的崩溃和标题跳转；后续消除这行空白。

## 当前行为

“粘贴并转换”以表格、图片等非文本块开头时，保留插入位置的前置文本段落。光标前有文字时保留该前缀；没有前缀时留下一个空段落，转换结果位于其后。前置段落通常保留原 `objectID`；原段落含子段落时，原身份随尾部文本和子段落保留，前置段落另建身份。原段落的列表、标签格式也会保留，可能显示为空列表项。

单段行内文本和以文本段落开头的块转换沿用原段落身份。写入后光标放在转换内容之后。整个粘贴只调用一次 `UpdatePageContent`，不调用 `NavigateTo`。

代价是结构块前可能多出一行，需要手动删除。OneNote API 的硬限制尚未证实。

## 已确认的问题

复现环境：Windows、x64 OneNote 桌面版 `16.0.20527.20112`、TeXShift Debug 加载项。

在活动文本编辑状态下，直接把原段落删除或替换为结构块，曾反复触发 OneNote 原生崩溃。Windows 事件记录为 `mso20win32client.dll`、异常码 `0x007a17e3`；加载项随后收到 RPC 错误 `0x800706BE`。鼠标点击实际按钮也能复现。OneNote 内部根因仍待确认。

先导航到标题再写入能够避开上述复现场景，但会产生可见的焦点和页面跳转，因此已移除。分两次写入、再删除空行会增加一次撤销；暂停重绘的实验出现写入完成后仍显示旧画面。单独修改 XML 选区、段落身份或附带标题的实验未通过稳定性回归。
