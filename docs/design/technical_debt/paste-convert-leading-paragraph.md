# 技术债：粘贴结构块时保留前置空段落

状态：待解决。2026-11-05，用户明确选择恢复空行方案，替换会跳转到页面标题的实现。

## 当前行为

“粘贴并转换”以表格、图片等非文本块开头时，保留插入位置的原文本段落及其 `objectID`。光标前有文字时保留该前缀；没有前缀时留下一个空段落，转换结果位于其后。原段落的列表、标签格式也会保留，可能显示为空列表项。

单段行内文本和以文本段落开头的块转换沿用原段落身份。写入后光标放在转换内容之后。整个粘贴只调用一次 `UpdatePageContent`，不调用 `NavigateTo`。

代价是结构块前可能多出一行，需要用户自行删除。保留这行是已获用户同意的临时方案；OneNote API 的硬限制尚未证实。

## 已确认的问题

复现环境：Windows、x64 OneNote 桌面版 `16.0.20527.20112`、TeXShift Debug 加载项。

在活动文本编辑状态下，直接把原段落删除或替换为结构块，曾反复触发 OneNote 原生崩溃。Windows 事件记录为 `mso20win32client.dll`、异常码 `0x007a17e3`；加载项随后收到 RPC 错误 `0x800706BE`。鼠标点击实际按钮也能复现。OneNote 内部根因仍待确认。

先导航到标题再写入能够避开上述复现场景，但会产生可见的焦点和页面跳转，因此已移除。分两次写入、再删除空行会增加一次撤销；暂停重绘的实验出现写入完成后仍显示旧画面。单独修改 XML 选区、段落身份或附带标题的实验未通过稳定性回归。

## 消债条件

在实际 Ribbon 路径下验证空文本框、已有正文、选区替换、表格开头和图片开头：无前置空行、无中途焦点跳转、无崩溃，一次撤销完整还原本次粘贴。保留周围正文、原有图片和插入位置，并在用户修改目标正文时拒绝覆盖。

继续保留 `piSelection` 读取和仅补全目标文本框二进制内容的性能优化；多笔迹页也要回归。后台调用成功或一次测试通过不足以关闭此项。

实现位于 `src/TeXShift.Core/OneNote/OneNotePasteInsertion.cs` 和 `OneNotePageWriter.cs`；回归入口为 `tests/TeXShift.Core.Tests/PasteConversionTests.cs`、`tests/TeXShift.Tests.E2E/Verify-Paste.ps1`。消债时同步更新当前要求保留前置段落的断言。
