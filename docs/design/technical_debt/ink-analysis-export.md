# 技术债：多笔迹页导出触发笔迹分析耗时

状态：待解决。开启自动手写笔迹识别时，新增笔迹后的转换仍可能耗时数秒。

## 复现与定位

在含 1122 个笔迹对象的页面新增笔迹，再转换普通 Markdown 或表格。粘贴并转换实测 2773 ms，撤销后重试相同内容降至 369 ms；普通转换为 1392 ms，撤销后为 251 ms。等待约 43 秒仍能复现慢读取。

主要耗时位于 OneNote `GetPageContent(piSelection)`：新增笔迹后约 1.1–1.4 秒，撤销后约 100–150 ms。粘贴转换读取页面和写入前校验各调用一次。一次 1272 ms 慢读取的 81 个栈样本中，61 个包含 `PopulateInkAnalysis`，63 个包含 `InkGraphLock`；内部反复处理的触发条件尚未查明。

已保留按需读取二进制数据、页面读取与渲染并行、分段计时。并行冷启动对照为 1015→803 ms，秒级笔迹分析耗时仍存在。

## 已验证路径

- 重启、Escape、同步、空更新及更换读取参数未稳定消除慢读取。修改时间戳不能可靠阻止过期写入，保留内容校验。
- 切页刷新并恢复选区曾做到转换 735 ms、粘贴转换 927 ms；仍有导航历史、选区恢复问题及 4.5 秒写入样本。
- 隐藏辅助页修改后撤销曾做到 481 ms，也出现 2.1 秒以上样本；撤销重置上下文本身会等待笔迹分析。
- 界面读文字加原生粘贴有亚秒级样本；整体替换可能重建文本框、改变位置和链接，默认粘贴会改格式，首次辅助页准备约 0.8–1 秒。
- 文本服务清空再富文本粘贴可保留位置和元数据，但需要两次撤销；拖放未替换原选区且丢失转换元数据。

上述原型均未接入正式流程，尚无证据确认 OneNote 存在无法绕过的硬限制。

## 缓解与验收

不需要自动识别的用户可在 OneNote 选项中关闭“启用自动手写笔迹识别”并重启。关闭后新增笔迹的读取约 142–150 ms；恢复开启后为 1313 ms。项目不自动修改此设置。

后续方案需在识别开启、多笔迹页新增笔迹后，使转换和粘贴转换稳定低于 1 秒，计入首次准备成本，并保留内容、格式、元数据、文本框位置与链接、选区及一次撤销。覆盖冷启动和日常操作穿插场景。
