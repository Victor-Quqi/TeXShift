# 开发环境

要求 Windows 10/11、x64 OneNote 桌面版、.NET Framework 4.8 和 `global.json` 指定的 .NET SDK。Visual Studio 可选。

```powershell
.\build.ps1 -Target Build -Configuration Debug
.\build.ps1 -Target Test -Configuration Debug
```

脚本自动恢复 NuGet 和固定版本的 MathJax。构建本身不写注册表，也不需要管理员权限。

## Debug 加载项

首次使用或仓库移动后，关闭 OneNote，在管理员 PowerShell 中注册一次：

```powershell
.\setup\Register-TeXShiftDev.ps1 -Action Register
```

注册项位于 64 位 `HKLM\Software\Classes`，OneNote Addins 项位于当前用户 HKCU。`DllSurrogate` 是 OneNote Click-to-Run 环境下的必要配置。

后续直接重新构建并重启 OneNote。DLL 路径不变，无需重新注册。状态检查无需提权：

```powershell
.\setup\Register-TeXShiftDev.ps1 -Action Status
```

Debug 和安装版使用不同的 CLSID/ProgID。两者同时注册会显示两套 Ribbon；移除 Debug 版需关闭 OneNote，并在管理员 PowerShell 中运行：

```powershell
.\setup\Register-TeXShiftDev.ps1 -Action Unregister
```

## 本地 E2E

`paste-convert --markdown "原有正文" --paste-input "test.md" --output ".\TestResults\paste" 验证粘贴转换，支持相同的选区参数和 `--driver core`。Ribbon 模式需先在“设置 → 常规”中开启按钮，运行时临时设置剪贴板并在结束后还原。

`paste-convert --empty-outline` 在测试页新建并激活空文本框，覆盖空白处粘贴；与 `--caret`、`--select`、`--outline` 互斥。`Verify-Paste.ps1` 默认通过实际按钮验证空框和已有文本框中的粘贴、选区替换、插入位置及图片保留，并检查表格和图片前无额外空段落。接受 `-Driver ribbon|core`、`-Configuration` 和 `-OutputDirectory`。

```powershell
.\tests\TeXShift.Tests.E2E\Verify-Smoke.ps1
.\tests\TeXShift.Tests.E2E\Verify-Paste.ps1
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe convert --input "test.md" --output ".\TestResults"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe convert --input "test.md" --select "{first paragraph}" "{last paragraph}" --output ".\TestResults"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe convert --page ".\TestResults\page.one" --caret "{paragraph text}" --output ".\TestResults"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe write-xml --markdown "Original text" --outline "Original text" --changes ".\tests\TestData\OneNoteWrites\replace-text.xml" --output ".\TestResults\write"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe reverse --page ".\TestResults\F04_Final_Page_XML_Basic_example.xml" --output ".\TestResults\reverse"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe reverse-xml --input-xml ".\TestResults\F04_Final_Page_XML_Basic_*.xml" --output ".\TestResults"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe dump --hierarchy
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe dump --page "{page-id}" --output ".\TestResults\page.xml"
.\tests\TeXShift.Tests.E2E\bin\x64\Debug\net48\TeXShift.Tests.E2E.exe verify-restore --pages "{page-id-1},{page-id-2}"
```

`convert` 和 `reverse` 默认使用 `--driver ribbon`，通过 Windows UI Automation 调用 OneNote 中实际加载的普通转换按钮；agent 只需执行 CLI。需要交互式 Windows 桌面，以及已注册、启用并重启加载的当前加载项。只启用一套 TeXShift Ribbon，避免同名按钮歧义。`reverse-xml` 使用已有 XML 快照执行离线反转。上述命令向 stdout 输出 JSON，并以退出码表示结果。`dump` 只读取 OneNote XML，默认将原始 XML 写入 stdout。`verify-restore` 会反复关闭并重新启动 OneNote，只用于开发机上的主动检查，见 `docs/design/e2e-onenote-restore.md`。

`convert` 默认把光标放在第一段（Markdown 页面为新增的空段），即 Cursor 模式；`--caret` 指定光标所在段落，`--select` 选中一段或一个段落范围（Selection 模式），`--outline` 选中整个文本框。这三个参数互斥，段落按所含文本匹配。`--page` 在测试笔记本中重现出问题的页面，接受 `dump --page` 的 XML 或从 OneNote 导出的单页 `.one`（保留页面全部数据）。

`write-xml` 共用上述建页、选区及收尾流程，将 `--changes` 模板直接交给 OneNote，便于隔离 XML 写入问题。它跳过转换器及生产写入器的选区处理。模板中的 `{{pageId}}`、`{{outlineId}}` 分别替换为临时页和当前选中文本框的 ID；`{{oe:0}}` 按深度优先顺序引用该文本框内的段落 ID，从零计数。没有选中文本框时使用第一个文本框。

`dump --page "页面 ID" --format one --output snapshot.one` 导出页面的原生快照，可作为 `--page snapshot.one` 的复现输入。`--format pdf` 导出当前页面布局；默认 `--format xml` 保持 XML 输出。`one`、`pdf` 均要求 `--output`，不支持 `--hierarchy`。

CLI 自动准备笔记窗口、选区和 Ribbon，等待实际加载项的命令完成记录，校验页面 ID，再采集最终 XML 和 PDF。结束后恢复原页面和 Ribbon 选项卡；只关闭自己启动的 OneNote。多个 CLI 实例不能同时运行。Ribbon 选项卡操作会把 OneNote 切到前台，错误弹窗也会影响焦点。`--driver core` 跳过 Ribbon，在 CLI 内执行 Core 流程，共用真实建页、选区、结果采集和清理；适合后台内容回归，不覆盖加载项装载、用户设置、按钮或弹窗。两种驱动都需要有窗口的 OneNote。Core 默认使用默认设置；`--settings <AppSettings JSON>` 可覆盖本次设置，例如 `--driver core --settings tests/TestData/Settings/math-images.json`。Ribbon 使用加载项已保存的用户设置，不接受该参数。

`Verify-Smoke.ps1` 覆盖非空段落光标、整个文本框、段落范围、公式、Mermaid、实际按钮反转、错误弹窗采集与关闭，以及原始 XML 写入。脚本断言转换结果及选区外内容，任一场景失败返回非零退出码。接受 `-Driver ribbon|core`、`-InputFile test.md`（仅测该输入）、`-Configuration Release` 和 `-OutputDirectory`。

`convert` 在恢复、清理和释放完成后输出最终 JSON。转换成功但收尾失败返回 `6`，诊断文件写入失败返回 `7`；已有转换错误的退出码保留。`--cleanup false` 保留测试页面，仍执行恢复和释放。恢复失败时保留测试资源。命令完成状态不明时保留测试页和 OneNote 会话，并报告收尾失败。

每次运行的 `F07_E2E_Run_*.json` 记录操作、驱动类型、启动方式、OneNote PID、原页面和测试页面 ID、各阶段耗时与错误、清理结果及退出码。`F09_Ribbon_Command.xml` 记录实际加载项的路径、版本、进程及关联的命令结果；失败时 `F10_UI.xml` 保存 UI 状态，错误弹窗另存为 `F11_Error_Dialog.txt`。输出目录始终保留。

普通按钮测试保存输入、转换前选区 XML、最终页面和选区 XML、PDF。转换器内部的 `F03`、`F06` 由 Core 驱动或产品的调试转换功能生成。运行日志中的命令记录不含笔记正文；采集的页面与 UI 文件按本地测试数据处理。

调试转换在调用 OneNote 前将实际写入请求保存为 `F03_Page_Changes_*.xml`（反向为 `R03_Page_Changes_*.xml`）。`write-xml` 还保存写入前的选区 XML 和 `F08_Final_Selection_*.xml`，用于比对编辑位置，并导出 `F05_Export_*.pdf` 检查实际布局。
